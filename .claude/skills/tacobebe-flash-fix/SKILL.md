# 타코베베 화면 깜빡임 없애기

## 1. 목적
손님이 화면을 열 때 위사 원래 화면이 0.3~1초 보였다가 타코베베 모양으로 바뀌는 깜빡임을 없앤다.
결과는 "머지된 PR + 위사 상단공통페이지에 붙여 넣을 코드 블록 + 실제 화면 확인 결과"다.
이 스킬은 takkobebe-link 저장소 작업이다. 다른 프로젝트에서 요청을 받으면 "takkobebe-link 프로젝트에서 진행"하라고 안내하고 멈춘다.

## 2. 원인 (2026-10-13 확인, 먼저 이해하고 시작)
- tkbb-main.js는 상단공통페이지에서 `defer`로 불린다. 원래 화면이 먼저 그려지고(약 0.7초) 그 뒤에 실행된다.
- 그래서 tkbb-main.js 안에서만 "숨김"을 걸면 이미 늦다. 깜빡임은 사라지지 않는다. (PR #156·#157에서 한 번 실패함)
- 해결은 두 부분이 짝이다.
  - A. 숨김: 상단공통페이지의 tkbb-main.js 줄 바로 위 인라인 script. 화면이 그려지기 전에 `html.tkbb-rvwait #cnt{opacity:0}`를 건다. 3초 안전장치 포함.
  - B. 보이기: tkbb-main.js가 새 모양을 다 그린 뒤 `tkbb-rvwait` 클래스를 지운다.
- 경로 목록은 두 곳에 있다: A의 `L` 배열, B의 `RVWAIT` 조건(또는 해당 블록의 경로 조건). 두 목록은 항상 같아야 한다.

## 3. 입력 받을 정보
- 필수: 어느 화면인가 (화면 이름 또는 주소). 모르면 "어느 화면을 누를 때인가요?" 한 가지만 묻는다.
- 있으면 반영: 폰/PC, 로그인 여부.
- 범위: 모바일 상단공통페이지만 다룬다. PC에서 깜빡인다고 하면 "PC는 상단공통페이지가 따로라 이 스킬 범위 밖"이라고 알리고, 원하면 PC용 블록을 별도로 안내한다.

## 4. 작업 절차
1. 화면 경로를 정한다 (예: 주문 목록 = `/mypage/order_list.php` [확인 필요]). 스킨 문서 3장 표를 쓰고, 표에 없으면 브라우저 주소창에서 `location.pathname`을 직접 확인한다.
2. 브라우저(내장 브라우저 우선)로 그 화면을 열어 확인한다.
   - 상단공통페이지 인라인 script에 그 경로가 이미 있는가 (`tkbb-rvwait` 검색)
   - 그 화면에 `#cnt`가 있고, 목록·게시판 같은 바뀌는 요소가 `#cnt` 안에 있는가
   - tkbb-main.js의 어느 블록이 그 화면을 다시 그리는가
3. 갈림길 (하나라도 해당하면 여기서 멈추고 보고한다)
   - tkbb-main.js가 그 화면을 다시 그리지 않는다 → 깜빡임 원인이 다른 곳(늦게 붙는 CSS, 스킨 자체 등)이다. 이 스킬 대상이 아니다. 확인한 원인을 보고하고 tacobebe-skin-edit로 넘긴다.
   - `#cnt`가 없거나 바뀌는 요소가 `#cnt` 밖에 있다 → 숨길 요소를 임의로 바꾸지 않는다. 실제 감싸는 요소 이름을 보고하고 진행 여부를 묻는다.
   - 경로가 A에 이미 있다 → 원인은 B(보이기 시점) 쪽이다. B 블록만 점검한다.
4. 저장소 작업 (tacobebe-skin-edit 3장 절차 그대로: 최신 main에서 새 브랜치, 다시 읽기, 필요한 줄만 Edit, node --check, rebase, diff, PR, 체크, 머지, 배포 확인)
   - 그 화면이 "마이페이지 하위 메뉴" 블록의 `PAGES`에 있으면: `var RVWAIT = ...` 조건에 경로만 추가한다. 보이기 코드는 이미 `start()` 끝에 있다.
   - 다른 블록(메인·상품상세·카테고리 등)이면: 그 블록에서 새 모양을 다 그린 직후, 실패했을 때 모두 `document.documentElement.classList.remove('tkbb-rvwait')`가 실행되게 한 줄씩 넣는다. 카테고리는 `tkbb-catwait`가 따로 있으니 거기에 맞춘다.
5. 순서 주의: B(저장소)를 먼저 머지하고 배포 확인을 한 뒤 A(상단공통페이지)를 바꾼다. 반대로 하면 그 화면이 3초 동안 빈 화면이 된다.
6. A 코드 블록을 만든다 (5장 틀). 기존 블록 전체를 바꿔 붙이는 형태로 준다. 경로 목록에는 기존 경로를 모두 남기고, B의 경로 목록과 하나씩 대조한다.
7. 위사 상단공통페이지 저장은 Claude 세션 안전장치가 막는다. 우회하지 말고 사용자에게 붙여 넣기 방법을 안내한다.
   - 위치: 위사 관리자 → 모바일 → 상단공통페이지 편집 (`/_manage/?body=wmb@layout&part=%7B%7BT%7D%7D`)
   - Ctrl+F로 `tkbb-rvwait` 검색 → 그 `<script>…</script>` 블록 전체를 새 블록으로 바꿈 → 저장하기
   - 블록이 없으면 `tkbb-main.js?v=` 줄 바로 위에 넣는다
8. 사용자가 "저장했어"라고 하면 브라우저로 화면을 다시 열어 확인한다 (6장 점검표).
9. 프로젝트 문서 "스킨-구조와-작업규칙" 1장 '깜빡임' 항목의 적용 화면 목록을 갱신한다.

## 5. 출력 형식
### A. 상단공통페이지 코드 블록 (경로 목록만 바꿔 쓰는 기본 틀)
```html
<!-- 깜빡임 막기: 새 모양이 그려질 때까지 원래 화면 숨김. 늦어도 3초 뒤엔 보임. 되돌리려면 이 script만 지운다 (갱신 YYYY-MM-DD) -->
<script type="text/javascript">
(function(){try{var L=['/shop/product_review_list.php','/shop/product_qna_list.php','/shop/product_qna.php'];var p=location.pathname;if(L.indexOf(p)<0||/[?&]tkbb_old=1/.test(location.search))return;var d=document.documentElement,s=document.createElement('style');s.textContent='html.tkbb-rvwait #cnt{opacity:0;}';(document.head||d).appendChild(s);d.classList.add('tkbb-rvwait');setTimeout(function(){d.classList.remove('tkbb-rvwait');},3000);}catch(e){}})();
</script>
```

### 보고 틀
**바뀐 것**
| # | 화면 | 바뀐 점 | 적용 값 |
|---|---|---|---|
| 1 | 주문 목록 | 새 모양이 다 그려질 때까지 본문 숨김 | 최대 3초 |

**PR**: 링크 — 머지 완료 / 보류(이유)
**붙여 넣을 곳**: 위사 관리자 → 모바일 → 상단공통페이지 편집, `tkbb-rvwait` 블록 전체 교체 → 저장하기 (위 A 블록)
**경로 목록 대조**: A `L` 배열 = B 조건 (경로 n개 일치)
**확인 결과**: 저장 후 확인한 화면별 결과 1줄씩 (확인 전이면 "저장하면 바로 확인할게요")
**되돌리기**: 상단공통페이지에서 이 script 블록만 지우면 원래대로
**[확인 필요]**: 추측한 것

3장 갈림길에서 멈춘 경우는 위 틀 대신 "확인한 원인 / 근거(화면·코드 위치) / 다음 단계 제안" 3줄로 보고한다.

## 6. 금지 사항 / 점검 체크리스트
금지
- tkbb-main.js 안에서만 숨김을 걸고 "해결"이라고 보고하기 (defer라 효과 없음)
- 3초 안전장치 없이 숨기기, `#cnt` 말고 `body`·`header` 숨기기 (상단 메뉴까지 사라짐)
- `#cnt`가 없는 화면에서 숨길 요소를 묻지 않고 임의로 바꾸기
- tkbb-main.js가 다시 그리지 않는 화면에 경로만 추가하기 (깜빡임은 그대로, 원인만 가려짐)
- `?tkbb_old=1`(원래 화면 보기) 주소에서 숨기기 (보이기 코드가 안 돌아 3초 빈 화면)
- 상단공통페이지 저장을 다른 방법(클릭·타이핑 자동화)으로 우회하기
- 상단공통페이지 코드에 배열을 이어 붙이는 함수 이름 쓰기 (위사 보안 장비가 저장 요청을 404로 막음). 목록 검사는 `indexOf`만 쓴다
- 기존 경로를 빼먹고 새 경로만 넣은 블록 주기
- A와 B 중 한쪽 경로 목록만 바꾸기

저장 후 확인 (화면마다)
- [ ] 페이지 소스에 `tkbb-rvwait` 인라인 script가 있다
- [ ] 그 script가 게시판·목록 요소보다 앞에 있다 (`compareDocumentPosition`)
- [ ] 로딩이 끝난 뒤 `html` 클래스에 `tkbb-rvwait`가 없고 `#cnt` opacity가 1이다
- [ ] 새 모양 요소(`.tk-wr` 등)가 있다
- [ ] A `L` 배열과 B 경로 조건이 같다
- [ ] 목록에 없는 화면(메인 등)은 영향이 없다
- [ ] `?tkbb_old=1`을 붙이면 숨김 없이 원래 화면이 바로 보인다
- [ ] 프레임 단위 녹화가 아니면 "폰에서 한 번 직접 확인해 주세요"를 덧붙인다

## 7. 좋은 예 / 나쁜 예
| 나쁜 예 | 좋은 예 |
|---|---|
| tkbb-main.js만 고치고 머지 후 "해결됐어요" | 저장소(보이기) 머지 → 상단공통페이지(숨김) 붙여 넣기 → 브라우저로 확인 |
| 새 경로만 든 블록을 줘서 후기·Q&A 깜빡임이 되살아남 | 기존 경로 + 새 경로를 모두 넣고 B 목록과 대조한 블록 전체 교체 |
| tkbb-main.js가 안 건드리는 화면에 경로만 추가해 3초 숨김만 생김 | 2단계에서 다시 그리는 블록이 없음을 확인하고 원인 보고 후 skin-edit로 넘김 |
