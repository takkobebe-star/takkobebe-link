# 타코베베 쇼핑몰 화면 수정 (tkbb-main.js)

## 1. 목적
위사 스킨이 불러오는 `tkbb-main.js`(3,000줄 넘는 파일, 여러 계정이 매일 수정)로 쇼핑몰 화면을 고친다.
목표는 "요청한 것만, 다른 사람 작업을 지우지 않고, 되돌리기 쉽게" 바꾸는 것이다.

## 2. 입력 받을 정보
- 어느 화면인가: 메인 / 상품 상세 / 마이페이지 / 마이페이지 하위(주문내역·주문상세·적립금…) / 후기 / 카테고리 / 1:1 문의
- 모바일만인가, PC도인가 (말이 없으면 모바일만. 대부분 블록이 PC에서는 `return` 한다)
- 무엇을 어떻게: 숫자로 (예: "여백 66→36px", "18px 세미볼드"). "좀 더 예쁘게"처럼 모호하면 시안 2개를 말로 제안하고 고르게 한다.
- 스크린샷이 있으면 받는다 (어느 요소인지 헷갈리지 않게).

## 3. 작업 절차
1. CLAUDE.md 1번: `git fetch origin main` → 새 브랜치. 고치기 직전에 파일을 다시 읽는다.
2. 블록 찾기: 파일은 `/* ===== 이름 (날짜) — 설명 =====` 머리 주석으로 나뉜다.
   `grep -n "^/\* =====\|^/\* ──" tkbb-main.js` 로 목록을 보고 해당 블록만 읽는다.
   주요 블록: 상단 장바구니 아이콘 / 메인 공구 일정·배너(`__TKBB_CAL`) / 상품상세 상단 정리 / 관심상품 / PC 메인 / 상품후기 / 후기 쓰기 상품선택 / 카테고리 바 / 마이페이지 / 마이페이지 하위 메뉴 / 1:1 문의 글쓰기 / 후기 작성 팝업.
3. 고치기: 필요한 줄만 Edit 로 바꾼다. 파일 전체 다시 쓰기, 들여쓰기 정리, 관련 없는 줄 이동 금지.
   바꾼 줄 끝에 짧은 주석과 날짜를 단다: `// 66→36px (2026-10-02)`.
4. 새 기능이면 새 블록을 비슷한 블록 근처에 추가한다 (4번 틀).
5. 점검: `node --check tkbb-main.js` 통과 → `git diff origin/main...HEAD` 에 요청과 상관없는 빨간 줄이 없는지 확인.
6. 커밋 메시지: `화면: 무엇을 어떻게` (예: `메인: 곧 오픈해요 위 여백 66→36px`). PR 설명에 확인할 화면 주소(예: `m.takkobebe.com/mypage/order_list.php`)를 적는다.
7. 사용자에게 알린다: Merge 후 최대 5분(캐시)이 지나야 보인다. 그래도 안 바뀌면 상단공통페이지 `tkbb-main.js?v=` 숫자를 올려야 할 수 있다 [확인 필요].

## 4. 타코베베 기준
새 블록 틀 (이 파일의 기존 방식):
```js
/* ===== 블록 이름 (2026-MM-DD) — 무엇을 바꾸는지 한 줄
   되돌리려면 이 블록만 지우면 된다. ===== */
(function(){
	if (window.__TKBB_이름) return; window.__TKBB_이름 = 1;   // 두 번 실행 막기
	if (window.browser_type === 'pc') return;                 // 모바일만
	if (location.pathname !== '/mypage/xxx.php') return;      // 해당 화면만
	var CSS = '...';                                          // 위사 스킨을 이기려면 !important
	var st = document.createElement('style'); st.id = 'tkbb-이름';
	st.appendChild(document.createTextNode(CSS));
	(document.head || document.documentElement).appendChild(st);
	function start(){ /* DOM 작업 */ }
	if (document.readyState === 'loading') document.addEventListener('DOMContentLoaded', start); else start();
})();
```
- 문법은 기존처럼 `var`·`function` (오래된 폰 브라우저 대비). 화살표 함수·`let`·`const`·템플릿 문자열은 쓰지 않는다.
- 선택자는 범위를 좁힌다 (`#revWriteAjaxDiv ...`, `#mypage ...`). `body *`, `div` 같은 넓은 선택자 금지.
- 위사가 나중에 그리는 요소는 `MutationObserver` 로 기다린다. 요소를 기다리려고 `setInterval` 을 돌리지 않는다 (배너 자동 넘김처럼 원래 반복하는 동작만 예외).
- 기능(주문·결제·후기 등록)은 건드리지 않는다. 모양과 링크만 바꾸고, 실패하면 원래 화면이 그대로 보이게 한다.

디자인 값 (이 파일에서 이미 쓰는 값만 쓴다):
| 쓰임 | 값 |
|---|---|
| 글자 | `#161616` / 보조 `#6A6A66` / 연한 `#9A9A94` |
| 브랜드 연두 바탕 | `#D1D798` · 포커스 테두리 `#B9C077` · 진한 연두 글자 `#7C8340`, `#3E4220` |
| 선 | `#EFEDE6`, `#DAD5C8` |
| 베이지 바탕 | `#F7F5EE`, `#EEEADF` |
| 모서리 | 카드·썸네일 7px, 큰 카드 12px, 버튼 5px, 칩 999px |
| 글자 크기 | 본문 13~14px, 보조 12px, 제목 16~18px. 11px 미만 금지 |
- 고객은 휴대폰으로 짧게 본다: 버튼 높이 44px 이상, 누르는 칸 사이 8px 이상.

## 5. 출력 형식
```
화면: (어느 화면, 모바일/PC)
바꾼 곳: tkbb-main.js 블록 "이름" — n줄 (+a / -b)
| 항목 | 전 | 후 |
|---|---|---|
| 곧 오픈해요 위 여백 | 66px | 36px |
점검: node --check 통과 · 관련 없는 삭제 없음
확인할 주소: m.takkobebe.com/...
PR: 링크 (Merge 후 약 5분 뒤 반영)
```

## 6. 금지 사항 / 점검 체크리스트
- [ ] `vercel deploy`·`npx vercel`·`git push --force` 를 쓰지 않았다
- [ ] 바꾼 줄이 요청한 블록 안에만 있다 (`git diff --stat` 이 `tkbb-main.js` 1개, 줄 수가 요청 크기에 맞다)
- [ ] `node --check tkbb-main.js` 통과
- [ ] 새 블록에 `__TKBB_` 중복 방지, `browser_type`·`pathname` 확인이 있다
- [ ] 표에 없는 새 색·새 모서리 값을 만들지 않았다 (필요하면 사용자에게 먼저 묻는다)
- [ ] 화면에 넣은 문구도 표시·광고 기준을 지킨다 ("최저가", "무조건", 근거 없는 "1위" 금지). 적립금·할인 숫자는 실제 위사 설정과 같은지 [확인 필요]
- [ ] 충돌이 나면 직접 해결하지 않고 사용자에게 어느 줄이 겹치는지 알렸다

## 7. 좋은 예 / 나쁜 예
- 좋은 예: `+ '.tkbb-cal.v2{padding-top:36px !important;}'` 한 줄만 바꾸고, 위 주석에 `곧 오픈해요 66→36 (2026-10-02)` 처럼 이유와 날짜.
- 나쁜 예: 여백 하나 바꾸려고 `tkbb-main.js` 전체를 Write 로 다시 씀 → 다른 계정이 아침에 고친 후기 블록이 사라진다.
- 나쁜 예: `div{border-radius:0 !important}` — 쇼핑몰 전체 모양이 깨진다.
