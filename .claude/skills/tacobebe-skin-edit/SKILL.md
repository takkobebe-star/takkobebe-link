# 타코베베 스킨 수정 → PR → 자동 머지

## 1. 목적
운영자가 말로 준 화면 수정 요청을 takkobebe-link 저장소에서 고치고, 다른 계정의 작업을 덮지 않는 PR로 올린 뒤 점검을 통과하면 Claude가 직접 main에 머지한다.
main 머지 = 실제 쇼핑몰 배포다. 결과는 "머지된 PR 링크 + 화면별 한 줄 보고 + 배포 확인"이다.

## 2. 입력 받을 정보
필수 (없으면 물어본다. 한 번에 최대 3개):
1. 어느 화면인가 (메인, 상품상세, 마이페이지, 주문 목록/상세, 주문서, 장바구니, 후기 쓰기, 상품후기 게시판, 1:1 문의, 공구 달력, 링크 페이지)
2. 무엇을 어떻게 바꾸는가 (수치, 문구, 위치)

있으면 반영: 스크린샷, 참고 사이트(29CM·컬리·오아시스 등), 시안 번호(A/B/C안).
스크린샷이 있으면 화면 이름을 직접 판단하고 묻지 않는다.
요청에 "PR만", "머지하지 마", "내가 확인할게"가 있으면 이번에는 머지하지 않는다.

## 3. 작업 절차
1. 요청을 번호 목록으로 쪼갠다. 한 메시지에 3~5개가 섞여 오는 것이 보통이다.
2. 최신에서 시작: `git fetch origin main` → `git checkout -B claude/<영문-작업명>-<MMDD> origin/main`
3. 저장소 CLAUDE.md를 읽는다. 머지 주체(사용자 vs Claude)는 이 스킬을 따르고, 그 밖의 규칙(직접 배포 금지, 강제 푸시 금지, 충돌 처리)은 CLAUDE.md를 따른다.
4. 대상 코드를 찾는다. 대부분 `tkbb-main.js`. 화면은 경로 조건(`/mypage/order_detail.php` 등)과 CSS 문자열 안의 클래스로 찾는다.
5. 수정 직전에 그 부분을 다시 읽고, 요청한 줄만 Edit한다.
6. 안 바뀌는 스타일은 위사 기본 스킨이 덮는 값부터 의심한다 (padding, 세로 구분선, border-radius:0, 이미지 max-width:50%, h3 padding). 선택자를 좁혀 덮고 `!important`는 필요한 속성에만.
7. `node --check tkbb-main.js`로 문법을 확인한다 (고친 .js 파일 전부).
8. PR 직전: `git fetch origin main` → rebase → `git diff origin/main...HEAD`. 요청과 무관한 삭제(빨간 줄)가 있으면 PR을 만들지 않고 고친다.
9. 충돌이 나면 직접 해결하지 않고, 겹치는 파일·부분을 사용자에게 알리고 멈춘다.
10. PR을 만든다. 제목 `<화면>: <바뀐 점>`, 설명 1~2줄.
11. 머지 전 관문(6장)을 모두 확인한다. 하나라도 걸리면 머지하지 않고 PR 링크와 걸린 이유를 보고한다.
12. 머지 직전 한 번 더 `git fetch origin main`. main이 그사이 바뀌었으면 rebase → diff 확인 → push 후 다시 11번.
13. 머지: `gh pr merge <번호> --merge --delete-branch` (기존처럼 Merge commit 방식. squash·rebase 방식, `--admin` 사용 금지).
14. 배포 확인: 1~2분 뒤 `https://takkobebe-link.vercel.app/<고친 파일>?t=<현재시각>`을 받아 이번에 바꾼 문자열이 들어 있는지 확인한다. 최대 5분까지 기다리고, 그래도 안 보이면 "배포 확인 안 됨"으로 보고한다.
15. 머지 후 화면이 깨졌다는 보고가 오면, 원인을 찾기 전에 먼저 해당 PR을 되돌리는 revert PR을 만들어 같은 절차로 머지한다.

## 4. 타코베베 기준
값 해석
- 숫자가 오면 그대로 적용한다. "66→36px", "모서리 -2px"는 현재 값에서 계산한다.
- "조금"만 오면 여백 10px, 글자 1px, 모서리 2px 단위로 바꾸고 적용 값을 보고한다.
- 따옴표 속 문구는 글자·띄어쓰기·괄호까지 그대로.

디자인 값 (새 요소는 이 안에서 고른다)
- 색: #161616 글자·검정 버튼 / #6A6A66 보조 / #9A9A94 약한 정보 / #D1D798 브랜드 연두 / #7C8340 올리브 / 선 #DAD5C8·#EFEDE6 / 바탕 #F7F5EE 계열
- 모서리: 썸네일·카드 7px, 버튼 5px, 큰 카드 12px, 칩 999px
- 글자: 본문 14px, 보조 13px, 캡션 12px, 제목 17~18px. 굵기 300/400/500/600/700
- 모바일 375px 기준, 좌우 여백 16px. 날짜는 2026.10.07
- 심플: 상자보다 줄 나눔, 아이콘·뱃지·D-day는 요청 없으면 넣지 않음. 사진은 꽉 채움.
- 같은 줄 버튼은 같은 너비·같은 모서리.

동작
- 깜빡임 금지: 확인 전 값은 `opacity:0`으로 두었다가 보여 준다.
- 오픈 예정·마감 공구는 가격을 숨긴다.
- 배송 후 취소/환불/반품·1:1 문의는 `/shop/product_qna_list.php`.
- 시안 비교가 필요한 열린 요청은 코드 전에 A/B안을 2~3줄씩 설명하고 고르게 한다.

## 5. 출력 형식
작업 끝에 아래 틀 그대로 보고한다.

**바뀐 것**
| # | 화면 | 바뀐 점 | 적용 값 |
|---|---|---|---|
| 1 | 주문 상세 | 입금계좌 값을 같은 줄 오른쪽으로 | text-align:right |

**PR**: 링크 — 머지 완료 / 머지 보류(이유 한 줄)
**배포**: 확인됨(몇 분 뒤) / 확인 안 됨
**확인 방법**: m.takkobebe.com/<경로>에서 무엇을 보면 되는지 1줄 (폰은 새로고침, 안 바뀌면 최대 5분 캐시)
**되돌리기**: "방금 것 되돌려줘"라고 하면 revert PR을 바로 머지함
**[확인 필요]**: 추측한 것 (없으면 생략)

## 6. 금지 사항 / 점검 체크리스트
금지
- `vercel deploy`, `npx vercel ...`, `git push --force`
- `gh pr merge --admin`, 브랜치 보호 규칙 우회, main에 직접 push
- tkbb-main.js 통째 재작성, 무관한 줄 정리·포맷 변경
- 예전 브랜치 재사용, 앞 대화에서 본 코드 기준 작업
- 비밀 값(캘린더 iCal 주소 등)을 코드에 넣기
- 화면 문구에 효능 단정·"100% 안전"·근거 없는 "1위"

자동 머지 관문 (모두 통과해야 머지)
- [ ] 요청 항목 수 = 처리 항목 수
- [ ] 최신 origin/main 위에서 작업했고 충돌이 없다
- [ ] diff에 요청 외 삭제가 없다
- [ ] `node --check` 통과
- [ ] PR의 체크(Vercel 미리보기 등)가 있으면 모두 성공 (`gh pr checks`), 진행 중이면 끝날 때까지 대기
- [ ] 결정 기록(마이페이지 B안, 배너 혼합 2안, 오픈 알림 제거 등)을 되돌리지 않았다
- [ ] A/B안을 아직 고르지 않은 요청이 아니다
- [ ] `api/` 파일, 파일 삭제, vercel.json의 기존 항목 변경이 없다 (있으면 머지 전 사용자 확인. vercel.json에 새 헤더 블록을 추가만 한 것은 통과)
- [ ] 새 `*-desc.txt`·img 폴더면 vercel.json CORS 헤더 추가
