# 타코베베 상세설명 HTML 제작

## 1. 목적
위사 상품 상세에 들어가는 코드형 상세설명(최대 폭 720px)을 매번 같은 구조·같은 말투로 만든다.
결과물은 저장소 루트의 `<slug>-desc.txt` 한 파일 + `vercel.json` 등록 한 블록이다.

## 2. 입력 받을 정보
꼭 필요한 것 (없으면 이것만 묻는다, 최대 3개):
- 상품명, 브랜드/제조사, 구성(옵션·세트별 내용)
- 공급사 상세 이미지 또는 상품 정보 문서 (원재료·소재, 크기·용량, 보관, 제조국, 인증)
- 공구 상품인지 상시 판매인지 (공구면 세트별 정가·공구가·혜택)

있으면 좋은 것: 촬영 사진, 고객 후기·문의, 배송 출고 요일, 참고할 기존 상세(예: "샐러드처럼").
사진이 아직 `img/<slug>/` 에 없으면 먼저 `tacobebe-detail-photos` 스킬로 정리한다.

## 3. 작업 절차
1. CLAUDE.md 1번대로 최신 main에서 새 브랜치를 만든다.
2. 가장 비슷한 기존 상세를 하나 골라 다시 읽는다 (식품=`salad-desc.txt`/`oil-desc.txt`, 어린이 용품=`pencil-desc.txt`, 세트 선물=`hanwoo-desc.txt`). 클래스 체계·`<style>`은 여기서 가져온다.
3. 접두어를 정한다: 영문 2글자, 기존과 겹치지 않게. 사용 중: ch dj eg hw kg lc lm nr ol(oil) pc rb sd ty ud bu kn.
   → 바깥 `<div class="tkbb-xx">`, 안쪽 클래스는 모두 `xx-` 로 시작.
4. 4번 섹션 순서대로 내용을 채운다. 사실은 받은 자료에 있는 것만 쓴다. 모르는 값은 `[확인 필요]` 로 남기고 지어내지 않는다.
5. 공구가 가격표가 있으면 클래스 이름을 반드시 `xx-price-ttl`(제목) · `xx-price-list`(목록) · `xx-price-ft`(아래 안내)로 쓴다.
   → `tkbb-main.js` 가 오픈 예정·마감된 공구에서 이 세 가지를 자동으로 숨긴다. 이름이 다르면 마감 뒤에도 가격이 보인다.
6. `.wing-detail-more-contents { min-height: Npx; }` 로 접는 위치를 정한다. 첫 화면(대표 사진 + 한눈에 보기)까지 보이게, 보통 700~1300px. 주석에 어디서 접는지 한 줄 적는다.
7. `vercel.json` 의 `headers` 에 이 파일 블록을 추가한다 (기존 블록 모양 그대로):
   `source: "/<slug>-desc.txt"`, `Access-Control-Allow-Origin: https://takkobebe.mywisa.com`, `Content-Type: text/plain; charset=utf-8`.
   사진 폴더도 `/img/<slug>/(.*)` 블록이 없으면 함께 추가한다.
8. 점검(6번 체크리스트) → 미리보기 → PR. PR 설명에 위사 관리자에 넣을 파일 주소를 적는다:
   `https://takkobebe-link.vercel.app/<slug>-desc.txt`
   (관리자에서 이 파일을 불러오는 방식은 [확인 필요] — 기존 상품과 같은 방식으로 넣는다. `.js` 판(`window.__TKBB_XX_DESC = "..."`)은 CORS 없이 `<script>` 로 넣어야 할 때만 만든다.)

## 4. 타코베베 기준
섹션 순서 (없는 항목은 건너뛴다):

| 순서 | 섹션 | 내용 |
|---|---|---|
| 0 | 공구 혜택·세트별 공구가 (공구일 때만, 맨 위) | 혜택 한 줄 + 세트별 번호·이름·구성·정가(취소선)·공구가·할인율 |
| 1 | 인트로 `xx-intro` | 대표 사진 → h2(위 `<span>` 한 줄 보조 + 아래 상품명) → 소개 2문장 → 한눈에 보기 4~6칸 |
| 2~4 | 특징 블록 2~4개 | 고객이 고를 이유. 제목 15자 이내, 사진 1장 + 설명 3줄 이내 |
| 5 | 활용·사용법 | "이렇게 드셔 보세요/써 보세요". 순서가 있으면 번호 목록 |
| 6 | 구성·크기·보관·원재료 | 크기 비교 사진(`size.jpg`), 용량·보관·소비기한, 원재료/소재 |
| 7 | 만든 곳 (있으면) | 산지·제조사 이야기 2~3줄 |
| 끝 | 배송 · 교환 및 상품 정보 | 아코디언: 언제 받나요 / 보관 / 배송·교환·환불 / 상품정보 고시 |

- 어린이 용품은 "아이가 써도 안심"(안전장치·KC 인증·사용 연령) 블록을 특징 블록 안에 꼭 둔다.
- 한눈에 보기 한 칸: `<b>` 12자 이내 + `<span>` 20자 이내. 숫자가 있으면 숫자를 앞에 (예: "한 팩 평균 320g").
- 말투: "~습니다/~드립니다", 한 문장 40자 안팎. 비교는 근거가 있는 숫자만 ("시중 샐러드는 230g 내외" 처럼 기준을 밝힌다).
- 상품정보 고시: 위사 값을 그대로 쓸 때는 `{{$상품정보고시리스트}}`. KC 인증번호·적합등록번호·A/S 처럼 꼭 보여야 할 값이 있으면 표(`xx-gosi`)로 직접 쓴다.
- 배송·교환 문구는 최근 상세(`oil-desc.txt` 끝부분)를 기준으로 하고, 출고 요일·배송비·제주 배송 여부만 상품에 맞게 바꾼다.

스타일 규칙:
- 루트: `max-width: 720px; margin: 0 auto;`, 색은 `--xx-ink #161616`, `--xx-muted #6A6A66`, `--xx-point #D1D798`, `--xx-deep #7C8340`, `--xx-line`, `--xx-surface` 변수로.
- `.tkbb-xx img { max-width: 100% !important; }` 는 지우지 않는다 (PC 스킨이 상세 이미지를 50%로 줄임).
- 사진 주소는 항상 절대 주소 `https://takkobebe-link.vercel.app/img/<slug>/파일`. 대표 사진 외에는 `width`·`height`·`loading="lazy"`·`decoding="async"` 를 단다.
- `alt` 는 사진에 실제로 보이는 것을 문장으로 (예: "연필을 꽂으면 저절로 깎인 뒤 올라오는 모습").
- 아코디언은 `<details><summary>질문<svg …chevron…></svg></summary>` 형식 그대로.

## 5. 출력 형식
작업이 끝나면 채팅에 아래만 짧게 보고한다:
```
파일: <slug>-desc.txt (새로 만듦/수정) · 접두어 xx
섹션: 1) 공구가 2) 인트로 3) … (순서대로 제목)
vercel.json: 추가함 / 이미 있음
[확인 필요]: (지어내지 않고 비워 둔 값 목록, 없으면 "없음")
표시사항 점검: 통과 n개 / 확인 필요 n개 (항목명)
위사에 넣을 주소: https://takkobebe-link.vercel.app/<slug>-desc.txt
PR: 링크
```

## 6. 금지 사항 / 점검 체크리스트
먼저 자동 점검을 돌린다 (태그 짝 · 사진 파일 · 공구가 클래스 · 접두어 · vercel.json 등록 · 금지 표현 · [확인 필요] 남은 곳):
`python3 .claude/skills/tacobebe-detail-html/check.py <slug>-desc.txt` → ✗ 가 없어야 PR. ! 는 문맥을 보고 판단.
- [ ] 접두어가 기존과 겹치지 않고, 모든 클래스가 `xx-` 로 시작한다 (다른 상세·스킨 CSS와 섞이지 않게)
- [ ] 공구가 표 클래스가 `-price-ttl/-list/-ft` 규칙을 따른다
- [ ] 360px·720px 폭에서 가로 스크롤이 없다 (playwright가 있으면 `file://` 미리보기 스크린샷 2장)
- [ ] `vercel.json` 이 JSON으로 읽힌다 (`node -e "JSON.parse(require('fs').readFileSync('vercel.json'))"`)
- [ ] 어린이제품: KC 인증 대상 여부·인증번호, 사용 연령, 소재, 제조국, 주의·경고 문구가 있다 (없으면 "담당자 확인 필요")
- [ ] 식품·건기식·화장품·세제: 해당 법령 표시 기준을 따로 확인하라는 메모를 PR에 남겼다
- [ ] 효능 단정("면역력 향상", "아토피 개선", "다이어트 효과"), 절대·최상급("100% 안전", "부작용 없음", "국내 최고", 근거 없는 "1위") 표현이 없다
- [ ] 인증·수상·판매량·비교 수치에 출처와 기준일이 있다
- [ ] 다른 상품의 desc 파일, `tkbb-main.js` 는 건드리지 않았다

## 7. 좋은 예 / 나쁜 예
- 좋은 예 (한눈에 보기): `<li><b>당일 생산 · 당일 발송</b><span>오전 9시 전 주문 기준</span></li>` — 사실 + 조건.
- 나쁜 예: `<li><b>최고의 신선함</b><span>무조건 당일 도착!</span></li>` — 근거 없는 최상급, 보장 못 하는 약속.
- 좋은 예 (어린이 용품): "뚜껑이 제대로 닫히지 않으면 전원이 들어오지 않습니다." — 작동 방식으로 안심을 준다.
- 나쁜 예: "아이에게 100% 안전한 연필깎이" — 절대 표현.
- 나쁜 예 (가격표): `<ul class="sd-prices">` — 숨김 규칙에 안 걸려 마감 뒤에도 공구가가 보인다.
