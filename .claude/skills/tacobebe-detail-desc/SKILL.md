# 타코베베 상품 상세설명 HTML (*-desc.txt)

## 1. 목적
공급처 자료(사진, 상세 이미지, 상품 정보)를 받아 타코베베 스타일의 모바일 상세설명 HTML을 만든다.
결과물은 takkobebe-link 저장소의 `<상품>-desc.txt` + `img/<상품>/` 사진 + vercel.json 헤더를 담은 PR이며, 점검을 통과하면 Claude가 직접 머지한다.

## 2. 입력 받을 정보
필수 (없으면 물어본다. 한 번에 최대 3개):
1. 상품명, 카테고리, 공급처
2. 사진 (대표 1장 이상) 또는 공급처 상세 이미지
3. 판매 방식: 공구(기간·세트별 공구가) / 상시 판매

있으면 반영: 세트·옵션별 정가·할인가(위사 옵션 가격 기준), 구성, 보관·소비기한, 배송 조건, 인증·시험 자료, 사용 연령, 경쟁 상품 대비 차이.
입력에 없는 수치·인증·후기는 쓰지 않고 [확인 필요]로 둔다.
요청에 "PR만", "머지하지 마"가 있으면 이번에는 머지하지 않는다.

## 3. 작업 절차
1. 소구 포인트 3~5개를 고른다. 특징마다 "그래서 엄마에게 뭐가 좋은가"를 한 줄로.
2. 아래 5장 섹션 순서로 원고를 먼저 쓴다 (블록당 제목 1 + 본문 3줄 이내).
3. 사진을 `img/<영문-상품명>/`에 저장한다. 이름: hero, size, pour, farm 등 내용 그대로. 긴 변 1080px 이하, jpg.
   공급처 상세 이미지에서 잘라 쓸 때는 글자가 박힌 부분을 피한다.
4. 기존 desc 파일 하나(최근 것: `salad-desc.txt`)를 열어 구조와 CSS를 참고해 새 파일을 만든다. 클래스 접두어는 상품마다 2글자로 바꿔도 되지만 최상위는 `.tkbb-sd`를 쓴다.
5. `vercel.json`에 `/<상품>-desc.txt`와 `/img/<상품>/(.*)` CORS 헤더 블록을 추가한다 (Origin `https://takkobebe.mywisa.com`). 기존 항목은 건드리지 않는다.
6. 아래 점검 체크리스트를 돌린다.
7. tacobebe-skin-edit의 PR·자동 머지 절차(최신 main, diff 확인, 머지 전 관문, `gh pr merge --merge`, 배포 확인)를 그대로 따른다. 배포 확인은 `https://takkobebe-link.vercel.app/<상품>-desc.txt?t=<시각>`과 대표 사진 주소가 열리는지로 한다.
8. 위사 상품 상세에 넣는 방법(파일 내용 붙여 넣기 위치)과 확인할 주소를 보고한다.

## 4. 타코베베 기준
레이아웃
- 최상위 `<div class="tkbb-sd">`, 그 안에 `<style>`. 모든 선택자는 `.tkbb-sd` 아래로.
- max-width 720px, Pretendard Variable (jsDelivr v1.3.9 dynamic subset), 14px / line-height 1.4 / letter-spacing -0.01em / word-break keep-all.
- 색 토큰: --sd-surface #F5F3EE, --sd-ink #161616, --sd-muted #6A6A66, --sd-line #E6E2D8, --sd-point #D1D798, --sd-deep #7C8340.
- 블록: `.sd-block` 위아래 32px, 블록 사이 1px 선. 상자 대신 줄 나눔(29CM식).
- 이미지: `width:100%; max-width:100% !important` (위사 PC 스킨의 50% 덮기), 첫 사진 외 `loading="lazy"`, alt에 사진 내용.
- `.wing-detail-more-contents { min-height: 1300px; }`로 첫 화면까지 보이고 나머지는 '상세설명 더보기'.

문구
- 다정한 해요체, 육아 선배 말투. eyebrow(작은 윗줄) 13px 올리브 + 제목 16~18px.
- 장점은 장면으로 말한다: "포만감 최고" 대신 "시중 샐러드 240g, 리셋 샐러드 320g".
- 공구가 표는 위사 옵션 가격과 1원도 다르면 안 된다. 할인율은 (1 - 공구가/정가)×100 반올림 (메인 배너와 같은 계산).
- 공구 기간은 본문에 쓰지 않는다 (일정은 캘린더가 관리, 오픈 예정·마감 시 가격은 스킨이 숨김).

## 5. 출력 형식 (섹션 순서)
1. `sd-top` 공구가 (공구일 때만): 혜택 한 줄 → 세트별 이름·구성·정가(취소선)·공구가·할인율 → 배송 한 줄(트럭 아이콘)
2. `sd-intro`: 대표 사진 → h2(윗줄 span + 상품명) → `sd-glance` 한눈에 보기 3~4줄
3. 고민 해결 `sd-solve`: "왜 OO가 어려울까요" → 해결 3줄
4. 특징 블록 2~4개: eyebrow + 제목 + 사진 + 본문 3줄 이내 + `sd-note`
5. 구성·보관(소비기한, 보관법, 용량)
6. `sd-faq` 아코디언(details): "배송 · 교환 및 상품 정보" 목록 + "상품정보 고시" 안에 `{{$상품정보고시리스트}}`
7. 맨 끝 관련상품 위사 템플릿 블록 (`{{if(관련상품리스트)}}…{{endif(관련상품리스트)}}`)을 기존 파일에서 그대로 복사

보고: 파일 목록, PR 링크(머지 완료 / 보류 이유), 배포 확인 결과, 위사에 넣을 위치, [확인 필요] 목록.

## 6. 금지 사항 / 점검 체크리스트
금지
- 의학적 효능 단정(면역력, 다이어트 효과, 아토피 등), "100% 안전", "무첨가"(근거 없음), 근거 없는 "1위"·판매량
- 가짜 긴급성("오늘만", "곧 품절")
- 위사 템플릿 변수(`{{$...}}`) 수정·삭제
- 다른 desc 파일·tkbb-main.js 수정
- `gh pr merge --admin`, main 직접 push, 직접 배포

점검 (하나라도 걸리면 머지하지 않고 보고)
- [ ] 공구가·정가·할인율이 위사 옵션 가격과 일치 (가격을 못 받았으면 [확인 필요]로 두고 머지 보류)
- [ ] 식품: 소비기한·보관법·원산지 표시, 식품표시광고법 기준은 "담당자 확인 필요"로 안내
- [ ] 화장품·세제·영양제: 해당 법령 표시 기준 확인 안내
- [ ] 어린이 사용 제품: KC 인증 대상 여부·인증번호, 사용 연령, 주의 문구
- [ ] 모든 img가 `https://takkobebe-link.vercel.app/img/...` 절대 주소
- [ ] vercel.json에 desc 파일·img 폴더 헤더 추가, 기존 항목 변경 없음
- [ ] 375px 폭에서 가로 스크롤 없음
