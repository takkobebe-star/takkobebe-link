# 타코베베 상세 사진 정리

## 1. 목적
공급사 상세 이미지·촬영 사진을 상세설명(`tacobebe-detail-html`)에서 바로 쓸 수 있게
규격·이름·용량을 맞춰 `img/<slug>/` 에 넣는다. 사진만 넣고 HTML은 건드리지 않는다.

## 2. 입력 받을 정보
- 사진 파일 (채팅 첨부 또는 연결된 폴더). 공급사의 세로로 긴 상세 이미지도 된다.
- 상품 slug (영문 소문자, 하이픈 가능. 예: `rice-bread`, `salad`). 없으면 상품명을 보고 제안한다.
- 어느 섹션에 쓸 사진인지 (모르면 사진을 보고 4번 표에 맞춰 제안)
- 사진 사용 권한: 공급사 제공 이미지를 써도 되는지 [확인 필요]로 PR에 남긴다.

## 3. 작업 절차
1. CLAUDE.md 1번대로 최신 main에서 새 브랜치를 만든다. 원본은 고치지 않고 복사본으로 작업한다.
2. 사진을 한 장씩 열어 본다. 긴 상세 이미지는 쓸 장면(제품 단독, 사용 장면, 단면, 크기 비교, 산지)을 좌표로 정해 잘라 낸다.
3. 잘라 낸 사진에 글자가 박혀 있으면 확인한다: 효능·최상급·근거 없는 수치("면역력 UP", "판매 1위")가 있으면 그 부분을 잘라 내거나 쓰지 않는다. 지울 수 없으면 사용자에게 알린다.
4. 4번 규격으로 크기를 맞추고 저장한다 (Pillow 예시는 5번 아래).
5. 크기 비교 사진(`size.jpg`)이 필요하면 흰 바탕 1000×560 에 제품과 기준 물건(500ml 캔, 성인 손, A4 등)을 나란히 두고 아래에 이름표를 단다 (`img/oil/size.jpg` 모양).
6. `vercel.json` 에 `/img/<slug>/(.*)` 블록이 없으면 추가한다 (`Access-Control-Allow-Origin: https://takkobebe.mywisa.com`, 기존 `/img/salad/(.*)` 블록과 같은 모양).
7. 결과를 표로 보고하고, 대표·크기 비교 사진은 미리보기로 한 번 보여 준다. 커밋 메시지: `<상품명> 상세: 사진 n장 (무엇)`.

## 4. 타코베베 기준
| 쓰임 | 파일 이름 | 가로×세로 | 형식·용량 |
|---|---|---|---|
| 대표 사진 (인트로 맨 위) | `hero.jpg` | 1000 × 1000~1250 (1:1~4:5 세로) | JPEG, 300KB 이하 |
| 본문 사진 | 쓰임을 영어로: `pour.jpg`, `farm.jpg`, `kit.jpg`, `bowl.jpg` | 가로 720~1000 | JPEG, 200KB 이하 |
| 크기 비교 | `size.jpg` | 1000 × 560 | JPEG, 흰 바탕, 80KB 이하 |
| 비교 두 장 (나란히) | `cmp-<이름>.jpg` | 440~450 × 360 | JPEG |
| 작은 칸 사진 (드레싱·옵션) | `<이름>1.jpg`… | 240 × 240 | JPEG |
| 움직임 (깎이는 모습 등) | `<동작>.webp` | 720 × 405 | 움직이는 WebP, 450KB 이하. GIF는 쓰지 않는다 (1MB 넘음) |

- 파일 이름: 영문 소문자·숫자·하이픈만. 한글·띄어쓰기·대문자 금지. 옵션이 여러 개면 `camel_fold.jpg` 처럼 `색_장면`.
- 모바일 첫 화면이 중요하다: 대표 사진은 제품이 가운데, 위아래로 꽉 차게. 아이 사진은 얼굴이 정면으로 크게 나오지 않는 컷을 고른다.
- 실사용 근거를 좋아하는 고객이다: 단면·사용 장면·실제 크기 컷을 우선, 연출용 배경 컷은 1장 이하.
- 사진 정보(EXIF, 위치) 는 지운다. 색이 누렇게 뜬 사진은 흰 균형만 살짝 맞추고, 실물과 달라 보이게 보정하지 않는다.

## 5. 출력 형식
```
폴더: img/<slug>/  (새로 만듦 / 추가)
| 파일 | 크기 | 용량 | 쓰일 섹션 | 원본 |
|---|---|---|---|---|
| hero.jpg | 1000×1250 | 140KB | 인트로 | 공급사 상세 1번 컷 |
vercel.json: 추가함 / 이미 있음
글자 박힌 사진 처리: (잘라 냄 / 사용 안 함 / 없음)
[확인 필요]: 공급사 이미지 사용 권한 등
```
저장 예시 (Pillow):
```python
from PIL import Image
im = Image.open(src).convert("RGB")
im = im.crop((x1, y1, x2, y2))              # 잘라 낼 좌표
im.thumbnail((1000, 1250), Image.LANCZOS)    # 쓰임별 최대 크기
im.save(dst, "JPEG", quality=82, optimize=True, progressive=True)  # EXIF 없이 저장됨
```

## 6. 금지 사항 / 점검 체크리스트
- [ ] 모든 파일이 4번 표의 크기·용량 안이다 (`python3` 로 크기·KB 출력해 확인)
- [ ] 이름 규칙(영문 소문자·하이픈)을 지켰고, 다른 상품 폴더 파일을 덮어쓰지 않았다
- [ ] 효능·최상급·근거 없는 수치·인증 마크가 박힌 컷을 쓰지 않았다 (KC 마크는 실제 인증이 확인된 경우만)
- [ ] 다른 브랜드 로고·경쟁사 상품이 보이는 컷이 없다
- [ ] 아이 얼굴·개인정보(주소, 송장)가 보이는 컷이 없다
- [ ] `vercel.json` 이 JSON으로 읽힌다
- [ ] 원본 파일은 그대로 두었다

## 7. 좋은 예 / 나쁜 예
- 좋은 예: `img/kongguk/size.jpg` 1000×560, 22KB — 흰 바탕, 제품과 기준 물건, 아래 이름표.
- 나쁜 예: `img/콩국/메인사진 최종.JPG` 3000×4000, 4MB — 한글·띄어쓰기 이름, 원본 크기 그대로.
- 나쁜 예: 공급사 컷을 그대로 잘라 "면역력 쑥쑥!" 글자가 남은 사진.
